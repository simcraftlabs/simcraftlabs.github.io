# Інтерактивний атлас України · 8 клас

Односторінковий навчальний атлас для курсу «Україна у світі: природа, населення» (8 клас НУШ). Один HTML-файл без залежностей: відкривається подвійним кліком, працює без інтернету, кладеться на будь-який шкільний сайт як звичайна сторінка.

**Файл:** `relief-ukraine-rivers.html` · ~999 КБ · 24 шари · перевірено в Chrome, Firefox, Edge.

## 1. Що вміє

| 2 | Клімат (Кеппен) | тема 2 | класифікація Кеппена, узагальнено |

| Для завдань | контурна карта (без гіпсометрії, суходіл білий — для друку й роздатки) |

**Інтерфейс:**
- ☰ **Шари** — висувна панель ліворуч (клавіша `L`/`Ш`, `Esc` закриває);
- **пресети уроків** у шапці, **у порядку тем програми**: Положення · Рельєф · Тектоніка й копалини · Клімат · Води · Ґрунти · Природні зони · Заповідники · Населення · Контурна карта (остання — це інструмент, а не тема). Один клік виставляє готову комбінацію;
- **чіпи активних шарів** унизу: клік — пояснення до шару, `×` — вимкнути;
- **нотатка до шару**: що показано → навчальний акцент → джерело → чесне застереження (модель/виміри, довоєнні дані, окуповані території). Розкривається кліком — **накладкою поверх карти**, тож не зменшує її. Уся нижня смуга ховається клавішею `B`;
- **легенда активної теми** будується автоматично з даних (колір, назва, % площі);
- **масштабна лінійка** внизу по центру — перераховується при кожному зумі, довжина обирається з круглих значень (100, 200, 250, 500 км…);
- **стрілка півночі** праворуч під кнопками масштабу;
- **накопичувальний рядок під картою** — під курсором показує все, що відомо про точку: область · висота · природна зона · ґрунти · тектонічна структура · значення активної теми · координати в градусах і мінутах. **Клік або тап фіксує рядок**, щоб прибрати руку з миші й розбирати з класом;
- **режим опитування** — кнопка в рядку, дубль у панелі або клавіша `H`: підказки під курсором (і рядок, і спливаюча висота) вимикаються, карта лишається. Клас відповідає — вмикаєте назад і перевіряєте;
- масштабування коліщам і кнопками `+ − ⌂`; спливаюча плашка біля курсора показує лише висоту й **вимикається окремо** (клавіша `T` або кнопка в панелі) — рядок унизу при цьому лишається;
- **повний екран** (`F`), **режим проєктора** — усі написи, і на полотні, і в інтерфейсі, на 28 % більші (`P`), **збереження карти в PNG** разом із легендою активної теми й рядком джерел.

**Принципові рішення щодо чесності даних:**
- узагальнені схеми (температури, опади, зони) прямо позначені як моделі, а не виміри;
- довоєнна статистика позначена; родовища й заповідники на тимчасово окупованих і прифронтових територіях мають зірочку `*`;
- історичні області показані лише підписами — чітких меж вони не мають, і малювати їх було б вигадкою;
- степ показано **однією зоною** (≈ 41 % території): межі його підзон — північної, середньої й південної — надто умовні для оглядового масштабу, тому їх названо в довідці, а не проведено на карті;
- заповідники показані значками без полігонів: у масштабі країни навіть найбільший обʼєкт ПЗФ менший за свій підпис;
- суходіл сусідніх держав малюється **завжди**, без галочки: інакше Україна висить у порожнечі, а море не читається як море.

## 2. Технічна архітектура

### 2.1. Один файл

Все всередині: дані, код, стилі. Жодних CDN, жодних запитів у мережу. Розкладка бюджету:

| Блок | Розмір |
|------|--------|
| `DEM` — модель рельєфу (base64 Int16) | 417 КБ |
| `UA` — полігони 25 регіонів (GeoJSON, спрощений) | 117 КБ |
| Зональні теми (`ZONES SOILS TECT CLIM PRECIP JANT JULT BASINS`) | ~232 КБ |
| `RIVERS` + `WATER` | 51 КБ |
| `NEIGH` — контури 7 сусідів, кордони, крайні точки | 31 КБ |
| Точкові шари (`MINERALS PROT CITIES CENTRES DENSITY URBAN HISTORICAL LABELS`) | ~42 КБ |
| Код (JS) | 45 КБ |
| HTML + CSS | 19 КБ |
| **Разом** | **~999 КБ** |

Фіксована частина (DEM + UA + NEIGH) — 565 КБ і більше не росте; кожен новий шар додає 2–30 КБ. Сервер віддає файл gzip-стисненим, фактичне передавання суттєво менше.

### 2.2. Проєкція та рендеринг

- Проєкція — рівнопроміжна циліндрична з поправкою на косинус середньої широти (`aspect = lonRange·cos(48,4°)/latRange`), реалізована вручну: `px(lon)`, `py(lat)`. Масштаб точний на середній широті країни; на краях карти похибка горизонтальних відстаней до 10 % — звичайна властивість цієї проєкції. Тому **масштабна лінійка рахується для широти центру того, що зараз на екрані** (`centreLat` → `kmPerPx`), а не для країни загалом: при наближенні до Криму чи Полісся вона лишається правдивою. Зум і панорамування — перерахунок вікна (`computeMap`), а не CSS-трансформація, тому підписи завжди чіткі.
- Рельєф: `DEM` розкодовується один раз (`decodeDEM`) у типізований масив; `renderElevation` малює гіпсометричну шкалу (`hypso`) в офскрін-канву, яку `draw()` лише масштабує. Тіньовий рельєф рахується з тієї самої моделі.
- `draw()` — єдиний головний цикл; порядок викликів у ньому = порядок шарів знизу вгору: суходіл сусідів → рельєф → заливка теми → вода → ареали копалин → історичні підписи → межі → річки → підписи рельєфу → центри/міста → значки копалин → значки ПЗФ → легенди значкових шарів.
- Зональні заливки малюються через один спільний `washFill(zones, canvas)`: полігони в окрему канву, потім `blur(5px)` — навмисно «мʼякі» краї, що чесно показують узагальненість меж.

### 2.3. Формати даних

Кожен шар — один `const` в голові скрипта.

```js
// зональна тема
ZONES = { zones: [ { name, fill, text, pct, label:[lon,lat],
                     lines?:[...],            // багаторядковий підпис
                     polys: [ [ [ [lon,lat], ... ] ] ] } ] }  // полігони з кільцями

// точковий шар (копалини, ПЗФ)
MINERALS = { fuel: { t, areas:[...], pts:[{n, g, xy:[lon,lat], o?, b?}], leg:[{g,t}] }, ... }
// g — гліф з таблиці MG; o:1 — окупована/прифронтова (зірочка); b:1 — підпис видно завжди

// картограма
URBAN = { regions: { 'Назва області': {u, fill, xy, note?} }, legend, kyiv, avg }
```

Координати скрізь географічні (lon, lat), округлені до 3 знаків. Полігони тем згенеровано офлайн (Python + shapely: буфери вздовж осьових ліній, обрізання по кордону `intersection(ukraine)`), у файл потрапляє лише готовий JSON.

### 2.4. Спільні механізми

- **`mineralGlyph(g,x,y,r)`** — усі значки (копалини + ПЗФ) з однієї таблиці `MG`: форма (`sq tri dia hex cir star bar sqd`) + колір + обвідка + внутрішня крапка.
- **`placePointLabel(boxes,x,y,R,txt,color)`** — розміщення підпису біля значка: під → над → праворуч → ліворуч, далі чотири діагоналі; перший вільний. `R` має бути **більшим за радіус заброньованої площі значка**, інакше підпис упирається у власний кружок і місто лишається без назви.
- **`themeLabels(...)`** теж має запасні позиції: назва зони описує велику площу, тож може стати поруч із точкою `label`, а не строго в ній — інакше при ввімкнених містах зона лишалася без назви.
- **`placeAreaLabel(...)`** шукає кільцями (18, 34, 50 px у восьми напрямках) — у щільних областях на кшталт Донеччини число мусить мати куди відійти.
- **Дві фази малювання.** Спершу **фаза значків** (`drawCitySymbols`, `drawCentreSymbols`) — усе, що має тіло на карті; кожен значок бронює своє місце в `symbolBoxes`. Потім **фаза підписів**, яка починається з перенесення цих броней у `labelBoxes`. Без цього поділу кружок міста малювався пізніше числа картограми й накривав його.
- **`placeAreaLabel(...)`** — підпис площинного обʼєкта (число області): за можливості в центрі, інакше вгору, вниз, вбік — сім варіантів. Значок міста на центрі області більше не ховає число.
- **`labelBoxes`** — **єдиний** реєстр зайнятих прямокутників для ВСІХ підписів карти. Обнуляється на початку фази підписів у `draw()`, і далі порядок малювання = порядок пріоритету:
  1. легенди бронюють своє місце заздалегідь (`drawMineralsLegend(true)`, `drawCitiesLegend(true)` — режим вимірювання, без малювання): вони малюються останніми й інакше накривали б підписи;
  2. **великі міста** (понад 500 тис.) — вони привʼязані до своєї точки, тоді як число області може відійти вбік;
  3. підписи активної теми: назви зон і числа картограм;
  4. форми рельєфу;
  5. решта міст (250–500 тис.; менші — лише при наближенні) та обласні центри;
  6. озера, річки;
  7. значкові шари: сусіди, копалини, ПЗФ.
  Той, хто малюється раніше, займає місце; наступні або зсуваються, або пропускаються. Перевірено скриптом, що рахує перекриття прямокутників на реальному малюванні: у щільних комбінаціях (тектоніка + три шари копалин + ПЗФ + міста, 117 підписів) — жодного наповзання.
- **`themeLabels(zones,opts)`** — підписи всіх зональних тем однією функцією (одно- та багаторядкові, з відсотком площі чи без).
- **`legendBlocks()` + `drawMineralsLegend()`** — легенди значкових шарів у лівому верхньому куті, до трьох поруч, з переносом і однією спільною виноскою про окуповані території.
- **`haloFor(hex)`** — колір обведення тексту за яскравістю кольору підпису.
- **`oblastAt(lon,lat)`** / **`zoneNameAt(zones,lon,lat)`** — область і зона під курсором (парний перетин променя по кільцях полігонів). На них тримається накопичувальний рядок: теми на карті взаємовиключні, але дані **всіх** шарів лежать у файлі, тому ланцюжок «зона → ґрунт → структура» показується цілком, навіть якщо намальовано лише одну з них. Саме тут учень бачить, що чорноземи типові тримаються лісостепу, а руди — щита.

### 2.4а. Режим проєктора

Розміри шрифтів розкидані по десятках функцій малювання, тому масштабуються **в одній точці** — перехопленням властивості `ctx.font` (`Object.defineProperty` на самому контексті, з відкатом на просту властивість, якщо в середовищі немає геттера в прототипі). `scaleFont()` множить будь-яке значення `NNpx` на `fontScale`. Наслідок, за який це й обрано: `measureText()` після цього рахує по збільшеному шрифту, отже перевірка накладання підписів і ширина плашок лишаються правильними без жодних додаткових правок.

Ширина плашок легенд рахується з реальної ширини тексту (`measureText` по найдовшому рядку), а не задається числом. Вимірювання показало, що фіксовані 158 px не вміщали «Національні природні парки» навіть при звичайному шрифті.

### 2.4б-1. Напрямок освітлення в тіньовому рельєфі

`shadeFactor(dzx, dzy)` освітлює з **північного заходу** — згори-зліва. Це не смак: зорова система припускає, що світло падає згори, і при освітленні знизу-справа спрацьовує **ілюзія інверсії рельєфу** — горби читаються як западини, а долини як хребти. Помилка знака в цій формулі не дає жодного попередження й виглядає просто як «щось не так із картою».

`dzx` — різниця схід−захід, `dzy` — південь−північ (рядки растра йдуть на південь). Схил, повернутий на північний захід, має обидві похідні додатними й мусить бути **світлішим**. Перевіряється тестом на синтетичному горбі.

### 2.4в. Контраст ліній

Стара одноколірна лінія `#4da6d9` губилася на зелених і жовтих заливках природних зон — виміряний контраст падав до 1,01, тобто річки зникали саме там, де потрібні найбільше. Тепер основна лінія `#0d63b8`, на чистому рельєфі її контраст 2,60 — цього досить.

Під тематичною заливкою додається світла підкладка (casing) на 1,8 px ширша, альфа 0,70: на світлих заливках працює лінія, на темних — підкладка, тож жоден фон не програшний (мінімум по 47 заливках 2,13, медіана 2,67). **Підкладка вмикається лише під заливкою** — на чистій карті й на контурній вона тільки шумить.

### 2.4б. Сталість розмітки

Полотно розтягується CSS-ом на всю висоту `.mw`, а внутрішній растр змінюється лише у `resize()`. Тому **будь-яка зміна висоти нижньої смуги без виклику `resize()` спотворює карту**: браузер розтягує старий растр, і виглядає це як посмикування.

Захист із двох боків:
1. `#status` має **сталу висоту** (22 px, 26 px у режимі проєктора), текст не переноситься — довгий хвіст ховається трикрапкою. Порядок у рядку не випадковий: область → висота → зона → ґрунти → структура → координати, тож першими зникають найменш важливі координати.
2. `ResizeObserver` стежить за самим контейнером карти й викликає `resize()` на будь-яку зміну розміру — перенос чіпів, розгортання нотатки, повний екран. Подія `resize` вікна в цих випадках не виникає.

### 2.5. Інтерфейс

Уся логіка інтерфейсу — окремий блок наприкінці скрипта. Ключове рішення: **старі галочки лишилися в DOM схованими** (`#oldTools{display:none}`), нова панель лише ставить `checked` і диспатчить `change`. Тому код малювання не залежить від інтерфейсу, і навпаки.

Реєстри, які треба поповнити, додаючи шар:
- `LAYERS` — рядок панелі (`k:'t'` тема / `k:'o'` накладка, група);
- `NOTES` — пояснення (що → акцент → джерело → застереження);
- `THLEG` — звідки брати легенду (для тем);
- за бажанням `PRESETS`.

Застереження: `draw()` викликає `activeTheme()` під час першого `resize()` — раніше, ніж виконається код інтерфейсу. Тому список тем оголошено `var THEME_IDS` (var спливає, const дав би temporal dead zone і білий екран).

### 2.6. Як додати новий шар (перевірений процес)

1. Згенерувати дані офлайн (Python), записати `const ІМʼЯ={...}` — компактний JSON, координати з 3 знаками.
2. Додати сховану галочку в `#oldTools`, прапорець `showX`, обробник `change`.
3. Написати `drawX()` і вставити виклик у `draw()` в потрібне місце порядку шарів (заливки — до меж, значки — після міст).
4. Значки — через `MG` + `mineralGlyph`; підписи — через `placePointLabel`; легенда значків — блок у `legendBlocks()`.
5. Доповнити `LAYERS` і `NOTES` (+ `THLEG`, якщо це тема).
6. `node test_ui.js` — має лишитися 38/38 (тест сам підхопить нову тему в перевірки легенд і нотаток).

### 2.7. Тестування

`test_ui.js` (jsdom, `npm i jsdom`) відкриває справжній файл із заглушеним `getContext` і проганяє 38 перевірок: побудова панелі, виключність тем, комбінування накладок, клавіатура, всі пресети, чіпи, легенда для кожної з 10 тем, нотатка для кожного шару, нуль JS-помилок при всіх увімкнених шарах. Геометрія перевіряється окремими офлайн-скриптами: кожна точка — у «своїй» області (point-in-polygon), ареали не виходять за кордон.
